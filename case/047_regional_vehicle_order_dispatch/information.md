# 区域配送车辆-订单分配

## 业务背景

帮我们把这批区域配送的订单派到车上。只要定"哪几单交给哪辆车"，不用排先后顺序、也不用给行车路线。一单只能给一辆车。车能装多少有讲究——上下限都随这一车拉什么货变（纯瓷砖、纯卫浴、定制品、混装，几档的门槛不一样），装太少不划算、装太多超限；每辆车还有能接的单数上限和一天的工时上限。有些订单跟某些车是配不上的（车限高、能不能进地下室、能跑哪些区域这些原因），有些订单之间也不能凑一车。同一车上的订单在地理上要凑得拢一点：跨的服务节点不能太散、彼此的方位角别岔得太开。我们希望总的运费低，同时一车的货尽量集中在少数几个服务区域、少数几个小区、少数几个大区里，一车覆盖的地理范围也别拉得太大。

## 产物形式

方案交一份 JSON 文件。

## 数据说明

- **载重区间字段的单位是吨，订单货物重量按公斤记**，比对之前要先换算到同一个单位上。
- **同车两单的方位角差上限是 45 度**。跨节点上限、单车接单数上限、工时上限则各车不同。
- **工时是这样算的**：这一车全部订单的作业工时之和，加上其中**行驶时间最长**的那一单的行驶时间（不是逐单累加行驶时间），再跟该车的工时上限比。
- **空车不参与载重下限判定**。

## 评估概要

**硬约束**（只有这一类会让方案直接判无效、一分不得）：

- **必须给出「哪辆车拉哪几单」的分配表**，分配表整个缺失或为空，方案不成立。
- **全部订单必须恰好各出现一次**：漏单或重复分配是结构性错误，整份方案直接判无效。这跟下面那些按比例罚分的「不达标」完全不是一回事——不达标只是扣分，漏单是出局。
- **车辆下标和订单下标都必须是整数、且落在数据里真实存在的范围内**，越界或写成字符串编号会被判非法。

**质量评分**：总账中不达标项的惩罚权重最高；其余项目中比较每车的地理范围、同车跨大区的订单对数和运费。

## 注意事项

- **订单与车辆互斥、两个互斥订单同车，这两类硬互斥关系一次都不能碰**：限高、能不能进地下室、可跑区域对不上就是配不上，没有「稍微差一点」的余地；载重、角度、跨节点、接单数、工时这几条则是差得越多越糟，差一点点和差一大截不是一回事。
- **地理集中度与运费各自怎么量**：**每车地理直径**是每辆车内部最远两单之间的距离；**同车跨大区对数**是同一车里属于不同大区的订单两两配对计数；**运费**是起步费 + 节点费 + 超载费；**服务节点数**和**小区数**统计的是「全部已分配订单覆盖到的不同服务节点／小区的个数」，是在整个方案上去重计数，而不是逐车统计再累加。
