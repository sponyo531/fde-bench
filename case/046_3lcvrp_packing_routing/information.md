# 三维装箱约束车辆路径（3L-CVRP）

## 业务背景

帮我们把这批货的送货车排一下。车都从配送中心出发，跑一圈把负责的客户送完再回来，每个客户只由一辆车服务、他家的货必须整批一起走、不能拆给两辆车。车是同一种车型，装的东西不能超过载重，更要紧的是货得**真的能装进车厢里**——箱子可以任意翻转摆放（长宽高怎么对着车厢的方向都行，但只能正着摆、不能斜放），彼此不能相互穿插重叠，也不能露出车厢外面。摆在上层的箱子底下要有东西托着，不能悬空架在半空中，底面大部分面积得压在下面箱子的顶面或者车厢底板上。我们最在意的是**用的车少**，一辆车就是一份成本；车数相同的时候再看谁跑的总路程短。请给我每辆车走哪些客户、按什么顺序走，以及每件货在车厢里摆在什么位置、翻转后的朝向是什么。

## 产物形式

方案交一份 JSON 文件。

## 数据说明
- **每种货带着一个件数，要展开成一件一件独立的货物实例**：件数是 3 就要摆成三件，三件各有各的位置和朝向。

## 评估概要

**硬约束**（任一条不满足，整份方案不作数）：
- **只交路线、不给三维摆放坐标是不行的**——没法校验装不装得下，直接判无效。每条路线都要给按访问顺序排的客户列表，以及这辆车里每一件货的起始角坐标和翻转后对应车厢三个方向的实际边长。
- **每个客户恰好被一辆车服务**，不能漏、也不能被两条路线同时服务。
- **每一件展开后的货物实例都恰好出现一次**：漏展开会被判货物覆盖不完整，同一件出现两次会被判重复装载。
- **货物实例编号有一条不可推的约定**：编号写成「原始货物编号#序号」、**序号从 0 开始数**（xxx#0、xxx#1、xxx#2）。自己另起一套编号、或者序号从 1 开始，会被判成「未知货物实例」、整份作废。
- **每件货必须放在服务它主人的那条路线上**，不能挂到别的车上。
- **翻转后的三个边长必须是原始长宽高的某个全排列**（六种轴对齐朝向），只能正着摆、不能斜放，也不能改尺寸。
- **单车载重不得超过车型的载重上限**。
- **坐标不得为负，也不得超出车厢的三个尺寸**；任意两件货不得有正体积的重叠。
- **底面支撑必须达标**（判据见「注意事项」第一条）。

**质量评分**：最重要的是使用车辆数；里程只在车辆数相同的方案之间再比较。

## 注意事项
- **底面支撑的判定口径**：凡是不落在车厢底板上（起始高度大于 0）的货，底面至少要有**四分之三**的面积被下方货物的顶面托住，否则判非法。两个容易翻车的细节：其一，托住的面积按**并集**算——把每一件「顶面顶在本件底面上」的下方货物与本件底面的重叠矩形都取出来，求并集面积再除以本件底面积；所以架在两个箱子之间的缝上、或者只压住下方箱子的一个角，都会因为比例不够四分之三而判非法，只检查「下面有没有东西垫着」远远不够。其二，只认顶面**严格贴平**本件底面的那些货物做支撑——下方货物的位置加高度必须正好等于本件的落位高度，留一丝缝浮在上面、或者坐标一路累加出零点几的误差，都会被当成「悬空无支撑」直接判非法。堆叠时高度必须严格对齐相加，不能凑近似值。
