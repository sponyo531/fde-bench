# 生产排产多目标优化（多批次 MIP 排产）

## 业务背景

帮我基于订单列表、产品列表、线体信息、工作日历等，做一份多批次生产排产，交一份排产结果明细：工单-订单-型号-线体-日期-班次-排产量。各批次的数据彼此隔离，整份方案还有统一的验收口径。排产目标按优先级从高到低：少未排：尽量把订单都排上，不要为了下面的集中类目标反而弃排；交期优先：在满足交期前提下优先用最优线体；无法满足交期时排产越早越好，交期早的订单尽量早排；整单生产：同一订单尽量在同一天内完成排产，减少订单切换；线体适配：型号尽量安排到高优先级线体；系列集中：同一产品及系列尽量集中、连续排产；产能均衡：各线体产能使用均衡，整体"前紧后松"、尽量往前排。产能约束：各线体每天所有产品 排产量×节拍 之和不超过线体日产能；允许 10% 弹性用于整单微调，但不能常态化按 110% 排。另外订单里有跟单的情况——有些行是必须跟着另一行走的，别给排散了。

## 产物形式

方案交一份 JSON 文件。

## 数据说明

- **各批次（sourceId）彼此独立**：每批各用自己的订单、产品、线体和工作日历，不能跨批次借线体、挪日期或凑单。
- **工单编码只在批次内唯一**：跨批次关联和汇总时必须把批次号和工单编码一起作为键。
- **节拍为 0 不是数据缺失**：它表示该产品不占线体产能，也不影响负荷率；若该行带跟随关系，仍须与父工单同日同线。
- **产品列表中的线体仍须能在线体信息和工作日历中找到**：没有日产能或排班日的线体不能用于排产。
- **工作日历里的效率列不另行折算日产能**：日产能直接使用线体信息中的数值。

## 评估概要

**硬约束**（下面每一条都逐批逐行校验，任何一个批次踩了一条，整份方案作废、五批总分一起归零，不给部分分）：

- **所有批次都必须覆盖**：任何一个 sourceId 缺失或踩中硬约束，整份方案一起作废。
- **产品能上哪条线是写死的**：每一条已排明细的（产品编码、线体编码）组合必须能在**同批次**的产品列表里查到，查不到就算违规。同一个产品在不同批次里的可用线体不一定相同。
- **排产日期必须是该线体的排班日**：（线体编码、排产日期）要能在同批次的工作日历里查到。日历只给了那么几天，超出日历范围、或者排到别的线体的班期上，都算违规。
- **产能红线是日产能的 110%**：某条线某天所有已排行的「排产量 × 节拍」之和不得超过日产能的 1.1 倍。
- **同一工单的总排产量不超过订单数量**：按工单编码聚合（带 `_余` 后缀的拆单余量记录单独算、不并进来），超一台就违规。
- **排产数量不能为负**。
- **跟随工单必须跟父工单同一天、同一条线**：父工单未排时，跟随工单也不能单独排；零节拍跟随行沿用父工单的线体和日期，不再单独校验自身的线体适配与排班日。

**质量评分**：按业务背景列出的目标优先级依次比较。


## 注意事项
- **排产台数按台数算不按条数**：「少未排」看的是已排上的台数占该批次全部工单订单数量之和的比例，不是把工单条数数一数；每个工单象征性排 1 台不算把单排上。
- **准时怎么量**：准时只看排产日期是否不晚于要求交付日期，交期一律以订单列表里的原始值为准（提交行上自报的交期不作数），按已排明细的条数算占比，早交不加分。
- **节拍是产能占用系数，不是工时**：产能按「排产量 × 节拍」汇总，节拍为 0 的行不进入产能占用与负荷率。
- **其余评分口径**：整单看同一订单的已排行是否同日同线；线体适配看已排行的线体优先级平均值；系列集中看各线体日期组合中的系列数；产能均衡看有排产的线体日期组合之间的负荷率离散程度。
