# 多仓库发货排程优化

## 业务背景

我负责规划订单哪一天从哪个仓库提单，需要优化多订单的发货时间及发货仓库。排的时候注意下，自己排产的货当天下线是发不出去的，得第二天才能用；缺货可以从工厂库往外租库调，反过来不行，外租库互相之间也不能调，另外有的品名是压根不许调的，调货还分调现成库存和调排产下线的货两种，调现成的划算些，这两种要分开标出来，调拨频次还有业务上限；有些订单指定了只能从外租库发，万一外租库没货，可以从工厂库调过去救急；还有库龄压太久的货要先清掉，某个仓某个型号有这种货没发完的话，先别再往这个仓调同型号的了。目标是延单尽量少，其次调货代价低一些。

## 产物形式

方案交一份 JSON 文件。

## 数据说明

- **规划窗口以发货日历为准**；仓库台账重复行先去重，工厂排产下线的货只进入工厂库。
- **只能从外租库发的订单怎么认**：订单表中运仓类型为「JSJ」的订单只能从外租库发；外租库缺货时，可以从工厂库调入后再发。
- **仓库库存里的负数**：现有库存负值逐条按 0 计，不作为负的初始余额，也不先与同仓同型号的正数行冲抵。
- **排产表里的零负行**：数量为 0 或负数的行不代表真实产出，不能作为供给。
- **排产下线的货要隔一天才能发**：下线日期严格早于发货日才算当天可用，当天下线当天不能发。
- **订单优先级列**：数值越小越紧急；这一列为空的订单按最不紧急算。
- **库龄达到配置表中超期天数的库存要优先清理**：同一仓库同一型号的超期库存尚未发完时，不得再向该仓调入这个型号。

## 评估概要

**硬约束**（下面任何一条被违反，整份方案作废、一分不得）：

- **发货日必须落在发货日历内**。
- **发货日不得晚于该订单自己的最晚发货日**：超期会直接判违规，而不是只计一次延单。
- **JSJ 订单必须从外租库发**：从工厂库直接发出就算违规，只能先调到外租库再发。
- **每个仓库每日的发货量不得超过该仓在台账中登记的日发货上限**。
- **调拨只能工厂库→外租库**：外租库不能往工厂库调，外租库之间也不能互调。
- **每个型号的调拨记录条数不超过 5 条**：按该型号的全部调拨记录统计，不按仓库对或日期分别统计。
- **每一个（仓库，型号）在窗口内每一天结束时的余额都不能为负**：不是只看整个窗口期末总量对得上就行。
- **外租库只能靠现货和调进来的货**：外租库不吃排产下线的货，工厂排产只进工厂库。
- **禁调品名不得调拨；同一订单号的所有行必须一起发或一起延**。

**一天之内的先后次序**：当天可用的排产先到位，然后调入、再调出，最后发货；当天调进的货当天可以发出。调拨触发日必须在发货日历内。

**质量评分**：最要紧的是延单尽量少，但看的不是张数，而是按紧急程度折算后的总份数；调拨代价只在延单打平时才起作用。

## 注意事项

- **延单按紧急程度折算份数**：最不紧急那档一张算 1 份，往上依次 3 份、4 份，最紧急那档延掉一张相当于延掉最不紧急的 5 张。
- **两类调拨代价差一倍**：调现成库存按一半计、调排产下线的按全额计，两类要分开标出来。
